# Клиентский путь и бэклог (SoundVault / torrent-streamer)

> Цель документа: показать, как **простой пользователь** (без эксперта, без Hermes)
> ставит и настраивает серверную часть и эндпоинты, и что надо доделать, чтобы этот
> путь стал реальностью. Состояние на 2026-11-06.

---

## 1. Клиентский путь (целевой UX)

Две роли: **владелец** (ставит сервер один раз) и **слушатель** (пользуется каждый день).

### Роль «Владелец» — установка с нуля

**Шаг 0. Предусловия**
- Есть сервер-машина (мини-ПК / NUC / старый ноут), на котором будет крутиться
  библиотека и плеер; на нём Docker.
- Есть устройства, которые будут физически играть звук (эндпоинты): колонки на
  MacBook, USB-DAC на мини-ПК, и т.п.

**Шаг 1. Установить сервер — одна команда**
```
curl -fsSL https://raw.githubusercontent.com/druner-ai/torrent-streamer/main/install.sh | bash
```
Скрипт поднимает `docker compose`, спрашивает:
- логин/пароль RuTracker (источник каталога);
- логин/пароль веб-интерфейса (кто может заходить);
- куда складывать музыку (путь библиотеки).

**Шаг 2. Открыть веб-интерфейс**
`http://<ip-сервера>:8000` → войти. Попадаешь в SoundVault.

**Шаг 3. Мастер первого запуска (в самом UI)**
- Экран «Источник»: проверить, что RuTracker доступен (каталог виден).
- Экран «Эндпоинты»: «скачайте приложение-эндпоинт на устройства, которые будут
  играть звук» (ссылки под каждую ОС).

**Шаг 4. Установить эндпоинты на устройствах воспроизведения**
- macOS: `brew install --cask soundvault-endpoint` (или `.dmg`).
- Linux: `sudo dpkg -i soundvault-endpoint.deb` (или AppImage).
- Windows: установщик `.msi`.
- Запустить один раз → endpoint **сам появляется** в веб-интерфейсе (mDNS).

**Шаг 5. Назначить аудиовыход**
В UI «Эндпоинты» → у каждого endpoint'а выбрать устройство вывода из **живого**
списка (подключил DAC — появился, отключил — пропал).

**Шаг 6. Слушать**
«Трекер» → выбрать раздачу → «Скачать» (качает qbittorrent и сам докачивает в
библиотеку) → Play → звук на выбранном endpoint'е.

### Роль «Слушатель» — повседневно
Открыть веб → выбрать endpoint/устройство → Play. Громкость, пауза, переключение —
всё из интерфейса, без терминала.

## 2. Текущий разрыв (что сейчас делает эксперт, а не пользователь)

Сегодня путь выше **невозможен без специалиста**. Реальные шаги (их делает Hermes):

1. Клонировать репозиторий и перенести код на NUC через `rsync` (NUC не git-репо,
   канонический код живёт на GitHub).
2. Собрать OAAT (`tune-bridge`) из исходников на Rust — отдельно на NUC (Linux) и
   MacBook (CoreAudio), с двумя нашими патчами (живой список устройств,
   `control_token`). Это **форк** апстрима, не готовый бинарь.
3. Настроить каждый endpoint вручную: `endpoint.toml`, сгенерировать `control_token`
   (openssl), поднять systemd-сервис (NUC) / ручной запуск (MacBook).
4. Заполнить `.env`: `QBT_PASS`, `RUTRACKER_LOGIN/PASSWORD`, `FRONTEND_AUTH`,
   `OAAT_CONTROL_TOKEN`, `PROWLARR_API_KEY`, `OAAT_ENDPOINTS` (ручные IP).
5. Поднять окружение каталога: qbittorrent + Prowlarr + FlareSolverr (обход
   Cloudflare на RuTracker).
6. Сеть для доступа извне: Tailscale + VPS B + Caddy reverse-proxy (Cloudflare Tunnel
   не работает — SNI-блок).

Каждый пункт — часы/дни ручной работы и системных знаний.

## 3. Бэклог (что доделать, чтобы закрыть разрыв)

Приоритет: P0 = блокер пути (без этого обычный пользователь не пройдёт), P1 =
usability/надёжность, P2 = продуктовые фичи.

### P0 — блокеры клиентского пути

1. **CI-сборка + упаковка эндпоинта в установщики.** ✅ Готово (2026-11-06/07):
   форк закреплён в `github.com/druner-ai/oaat` (private), GitHub Actions Release
   собирает `tune-bridge` под macOS (arm64+x86_64), Linux (x86_64+arm64 tar.gz +
   `.deb` amd64/arm64) и Windows (zip); `ts-controller` — в linux-артефактах.
   Stable-алиасы `releases/latest/download/...` для установщиков. Теги `v0.2.8-ts.N`.
   Вне скоупа осталось: `.dmg`/`.msi`/brew cask (тарболы + скрипты установки покрывают
   «скачал и запустил»; dmg/msi — косметика подписи, дорого без Apple Dev ID).

2. **Автодетект эндпоинтов (mDNS).** ✅ Готово (2026-11-06, 21286be):
   endpoint анонсирует себя (`_oaat._tcp`), backend резолвит кандидатов
   `mdns:NAME` с fallback на прямой адрес, TTL-кэш + watchdog переподключает
   ts-controller при смене адреса. НОВЫЕ устройства без записи в `.env`
   появляются сами: кэш обзора `_oaat._tcp` (TTL 30с, sticky при морганиях),
   discovered-endpoint'ы в `/api/endpoints` с флагом `auto`, выбор/активация
   без конфига, zero-config старт (пустой `OAAT_ENDPOINTS` больше не крашит).
   Ограничение среды: Keenetic режет mDNS-multicast WiFi→Ethernet — в такой сети
   фактически работает Tailscale-fallback.

3. **Мастер первого запуска в веб-интерфейсе.** ✅ Готово (2026-11-06, c1d6376):
   `GET /api/setup/status` (missing: rutracker/endpoint/qbittorrent) +
   `SetupWizard.jsx` при первом входе: форма RuTracker с проверкой логина,
   форма qBittorrent, экран эндпоинтов (живой список + ссылки на скачивание под
   все ОС). qbt-креды и пароль админки (Basic Auth) пишутся в БД и применяются
   БЕЗ перезапуска (env остаётся fallback). Путь библиотеки — не setting
   (определяется save_path qbittorrent), из мастера исключён.

### P1 — usability и надёжность

4. **Автозапуск endpoint'а из установщика.** ✅ Готово (2026-11-07, oaat 42a623b,
   релиз v0.2.8-ts.2+): `.deb` — postinst `systemctl enable+start
   oaat-endpoint.service` (prerm — stop+disable), конфиг из sample; macOS —
   `install.sh` + LaunchAgent (RunAtLoad+KeepAlive) в tar.gz; Windows —
   `install.ps1` (HKCU Run) в zip.

5. **Безопасность «из коробки».** ✅ Готово (2026-11-07, oaat 42a623b + backend
   3b53896): `control_token` генерируется автоматически при первом запуске
   (uuid v4, state-файл `<config>.token`, 0600), авто-токен публикуется в mDNS
   TXT `token=` (config-токен НЕ публикуется) и подхватывается backend'ом
   (приоритет: TXT > настройка `ep_token:<name>` > env `OAAT_CONTROL_TOKEN`).
   Кнопка регенерации в настройках UI → `POST /api/endpoints/regenerate_token`
   → endpoint удаляет state-файл и выходит → супервизор перезапускает с новым
   токеном (409, если токен задан конфигом). Проверено вживую на NUC (409 для
   config-токена).

6. **Публичный доступ одним флагом.** ✅ Готово (2026-11-07, 70ccd78):
   compose-профиль `public` — sidecar `tailscale/tailscale` в netns backend'а;
   включить = `TS_AUTHKEY` в `.env` + `docker compose --profile public up -d`,
   SoundVault виден в tailnet на :8000 без проброса портов. ⚠️ Не включать на
   хосте с уже работающим tailscaled (NUC — там доступ уже через host-tailscale
   + Caddy на VPS B).

7. **Авто-пауза при пропаже устройства.** Снял наушники / отключил DAC → плеер сам
   встаёт на паузу (детект пропажи устройства в живой список + пауза). Сейчас трек
   «играет в пустоту».

### P2 — продуктовые фичи

8. **Мультиюзер.** Сейчас один Basic Auth на всех. Нужны аккаунты/приглашения, чтобы
   у каждого члена семьи был свой вход.
9. **Мобильные эндпоинты (Android/iOS).** Телефон/планшет как endpoint (APK/iOS-приложение).
10. **OTA-обновление эндпоинтов.** Кнопка «обновить» в UI вместо ручной переустановки.
11. **Плейлисты / избранное / кэш обложек.** Локальное курирование, офлайн-обложки.
12. **Управление RuTracker-аккаунтом и капчей через UI.** FlareSolverr хрупкий; вынести
    статус/перезапуск обхода Cloudflare в интерфейс.

## 4. Порядок работ (рекомендуемый)

1. P0.1 (CI-сборка эндпоинта) — снимает самый большой блокер, сразу даёт «скачал и
   запустил».
2. P0.2 (mDNS) — эндпоинты появляются сами, исчезает ручной `OAAT_ENDPOINTS`.
3. P0.3 (мастер в UI) — исчезает ручной `.env`.
4. P1.4 + P1.5 — «поставил и забыл» (автозапуск + безопасность).
5. P1.6 (публичный доступ) — доступ извне без сетевого эксперта.
6. Остальное по потребности.
